# 验证与实机验收

## 离线检查

在仓库根目录：

```sh
python3 tools/build_content.py
python3 tools/validate.py
python3 -m unittest discover -s tests -v
python3 tools/package.py --game-version 1.13
python3 tools/package.py --game-version 1.14
git diff --check
```

`validate.py` 检查结构解析、namespace/事件引用、关键本地化引用、中英键集合、BOM、生成参数、阈值顺序、附加pulse及禁止的战争目标效果。它不是引擎词汇白名单或scope类型检查器。

`script_vm.py` 直接执行提交的 Clausewitz AST，覆盖种群资格、紧张度、请求、保障、违约、失效清理及疲劳；未知测试指令报错。时间过期、真实外交博弈、AI、战斗、修正实际影响、游戏存档以及渲染不在该解释器能力内。限时变量由测试显式移除或赋值，不模拟引擎日历。

## 每个版本单独执行

1. 启动1.13或1.14的干净播放集，启用本Mod并开新档，运行至少两个月。检查 `logs/error.log` 与 `game.log` 中的 `fia_`/`fia.`、未知指令和无效scope。不能只按命名过滤，因为有些引擎错误只显示文件路径。
2. 在国教国家选择有足够非国教人口的高动乱地区；正常积累或在控制台 effect 中对选定state设置 `fia_tension` 与 `fia_incident`。保持 `fia_case_owner` 和 `fia_faith` 正确，不使用硬编码state id。
3. 25触发国内事件，分别验证调解、调查、镇压；确认一年冷却、行政成本和受影响宗教激进者变化。
4. 50重大事件，70保护国邀请。让保护国拥有同教国教、当地利益、50以上威望、独立且和平；不满足者不应收到邀请。
5. 接受邀请，目标国分别接受或拒绝。记录目标国家与地区文本是否正确、是否出现重复请求。
6. 拒绝后，从原版外交视图选“保障宗教权利”和绑定地区。确认其他地区、无资格国家、停战对象不能使用。核对恶名与筹码实际费用及目标控制要求。
7. 测试目标国退让、保障目标被和平接受、保护国败北、白和。只有前两种应创建保障。
8. 战争中让限时理由过期、紧张度降低、受影响宗教占比降低、疲劳≥60。已有目标应仍在，不再允许另开新博弈。
9. 保障开始后检查地方修正、每年一次对指定宗教的去激进化、保护国监督成本；到59个月不能发奖，到60个月只发一次。
10. 测试撤回承诺、主动撤销保障、地区割让、吞并保护国、吞并目标国、革命。不能有悬挂成本、跨国错误清理或无条件再战。
11. 分别在邀请、请求、战争、保障阶段保存再加载；进行一次两人联机和hotjoin。相同存档不得发生不同任务绑定或重复奖励。
12. 全局观察至少20年：统计危机数、战争数、AI开战倾向、财政影响与月度性能。若AI不主动使用custom博弈，记录为集成缺陷，不能用“可能支持”替代结果。

目前没有运行上述游戏步骤；仓库只记录可重现的离线结果。
